AUTORAG ARCHITECT — REST API SPECIFICATION
Version 1.0 | Backend Team | Updated: June 2026

BASE URL: https://api.autorag-solutions.com/api/v1

All requests must include:
  Authorization: Bearer <JWT_TOKEN>
  X-Organization-ID: <ORG_UUID>
  X-Trace-ID: <UUID_V7>  (generated by client if not provided; propagated through all service layers)
  Content-Type: application/json

All responses follow the standard envelope:
  {
    "status": "success" | "error",
    "data": <object or null>,
    "error": { "code": string, "message": string, "details": object } | null,
    "request_id": <UUID>
  }

ENDPOINT CATALOG

1. POST /configurator/start
   Initiates a new pipeline configuration session (6-step wizard).
   Request body: { "project_id": uuid, "name": string }
   Response: { "session_id": uuid, "step": 1, "expires_at": ISO8601 }
   Notes: Session expires after 2 hours of inactivity.

2. POST /configurator/step/{step_number}
   Submits data for a specific configurator step (1 through 6).
   Step 1 — Document Upload: { "document_ids": [uuid] }
   Step 2 — Chunking Strategy: { "strategy": "semantic" | "hierarchical" | "late", "chunk_size": int, "chunk_overlap": int }
   Step 3 — Retrieval Config: { "retrieval_mode": "dense" | "hybrid", "top_k": int, "reranker": "cohere" | "bge" | "none" }
   Step 4 — LLM Config: { "provider": "gemini-flash-3.5" | "kimi-k2.6", "temperature": float, "max_tokens": int }
   Step 5 — Evaluation Thresholds: { "min_unified_score": float, "min_faithfulness": float }
   Step 6 — Review and Launch: { "confirm": true }
   Response: { "step": int, "valid": bool, "errors": [string], "next_step": int | null }

3. POST /pipelines
   Creates and launches a new pipeline from a completed configurator session.
   Request body: { "session_id": uuid }
   Response: { "pipeline_id": uuid, "job_id": uuid, "status": "queued" }

4. GET /pipelines
   Lists all pipelines for the authenticated organization.
   Query params: page (int), limit (int, max 100), status (string), sort_by (string)
   Response: { "pipelines": [PipelineObject], "total": int, "page": int, "limit": int }

5. GET /pipelines/{pipeline_id}
   Returns full pipeline details including latest run summary.
   Response: PipelineObject with embedded latest_run field.

6. POST /pipelines/{pipeline_id}/run
   Triggers a new evaluation run on an existing pipeline.
   Request body: { "trigger": "manual" | "scheduled" }
   Response: { "run_id": uuid, "job_id": uuid }

7. GET /jobs/{job_id}
   Polls the status of a long-running LangGraph job.
   Response: { "job_id": uuid, "status": "queued" | "running" | "completed" | "failed", "progress": int, "current_node": string, "estimated_remaining_seconds": int | null }

8. POST /ingest
   Uploads and queues a document for ingestion into the vector store.
   Content-Type: multipart/form-data
   Form fields: file (binary), pipeline_id (uuid), metadata (JSON string)
   Response: { "document_id": uuid, "job_id": uuid, "status": "queued" }

9. GET /documents
   Lists documents for the organization.
   Query params: pipeline_id (uuid, optional), status (string), page (int), limit (int)
   Response: { "documents": [DocumentObject], "total": int, "limit": int, "offset": int }

10. GET /documents/{document_id}
    Returns document detail including chunk count and metadata.
    Response: DocumentDetailObject

11. POST /retrieve
    Executes the 4-stage retrieval stack (dense → hybrid → rerank → HyDE) against a pipeline.
    Request body: { "query": string, "pipeline_id": uuid, "top_k": int (default 5) }
    Response: { "chunks": [ChunkObject], "rewritten_query": string, "latency_ms": int }

12. GET /score/{run_id}
    Returns evaluation scores for a completed pipeline run.
    Response: { "unified_score": float, "faithfulness": float, "recall_at_5": float, "context_precision": float, "latency_p95_ms": int, "cost_per_query_usd": float, "adversarial_pass_rate": float }

13. POST /deploy
    Submits a pipeline run for blue/green deployment to production.
    Request body: { "run_id": uuid, "approval_token": string | null }
    Response: { "deploy_id": uuid, "status": "pending_approval" | "deploying" | "deployed" }
    Notes: Unified Score >= 0.85 required for autonomous deploy. Score 0.70-0.84 requires approval_token from HITL flow.

14. POST /deploy/{deploy_id}/rollback
    Triggers rollback of an active deployment.
    Request body: { "reason": string }
    Response: { "rollback_id": uuid, "status": "rolling_back", "estimated_completion_seconds": int }

ERROR CODES

PIPELINE_NOT_FOUND (404): The specified pipeline_id does not exist or belongs to a different organization.
SCORE_GATE_FAILED (422): Unified Score below 0.85 and no valid approval_token provided.
FAITHFULNESS_HARD_BLOCK (422): Faithfulness score below 0.50; deployment is permanently blocked for this run.
JOB_IN_PROGRESS (409): A job is already running for this pipeline; concurrent runs are not permitted.
RATE_LIMITED (429): Request rate exceeds 100 requests per minute per organization.
UNAUTHORIZED (401): JWT token is missing, expired, or invalid.
FORBIDDEN (403): Organization does not have permission for the requested operation.
