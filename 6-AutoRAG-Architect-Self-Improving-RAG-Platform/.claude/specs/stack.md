## 3. Python Standards & Tooling

To ensure elite code quality across all **28 contributors**, the python backend enforces strict linting and formatting gates:

### Automated Formatters

- **Ruff** (Replaces Black, Flake8, and Isoort): Enforces styling rules and imports organization.
- **MyPy**: Enforces 100% strict type safety.
- **Pytest**: Backend unit and integration testing engine.

### Mandatory Coding Rules

1. **Separation of Concerns**: Keep agent logic (LangGraph nodes) strictly separated from the HTTP transport layer (FastAPI routes).
2. **Stateless Operations**: No global states or mutable variables are allowed inside agent nodes. All data must flow through the typed **LangGraph State**.
3. **Typing**: The use of `Any` is strictly forbidden unless explicitly justified. Use Pydantic models for all API schemas.

## 4. Frontend Standards

The frontend dashboard is built to give a premium, light-first "AutoRAG Intelligence Control Center" visual experience for tracking agent evaluation cycles (ADR-008 light-first flip, ADR-010 earth-tone token implementation — see `docs/frontend_design.md`, the authoritative design SOT). No glassmorphism/backdrop-blur in the light theme; dark mode is a fully supported opt-in, not the default:

- **Framework**: Next.js 15 (App Router)
- **Styling**: Tailwind CSS (required — light-first with dark-mode opt-in via `next-themes`, mobile-first, shadcn/ui components).
- **State Management**: React Context / Hooks (stateless server-side rendering preferred).
- **Formatters**: Prettier + ESLint.
