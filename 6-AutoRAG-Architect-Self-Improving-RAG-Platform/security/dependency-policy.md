# AutoRAG Architect — Dependency Policy

**Version**: v4.0 | **Updated**: 21-Jul-2026
**Owner**: Team 10 (Mahesh Kumar)
**Enforcement**: CI via `pip-audit` + `npm audit` in `security.yml`

---

## Rule 1 — No HIGH or CRITICAL CVEs

Before adding any package (Python or Node), check for known vulnerabilities:

```bash
# Python — after adding to pyproject.toml and running uv sync
cd autorag-server && uv run pip-audit

# Node — after running npm install
npm audit --workspace=autorag-client
# (vscode-extension workspace removed 17-Jul-2026 -- F-10 backlog, scaffold
#  had zero real dependencies; recreate this line if the workspace returns)
```

**Thresholds:**

| Severity | Action |
|----------|--------|
| CRITICAL | ❌ Do not add. Find alternative. |
| HIGH | ❌ Do not add without lead approval (Mahesh Kumar). |
| MEDIUM | ⚠️ Document the risk. Get peer review. |
| LOW | ✅ Acceptable. Log in PR description. |

---

## Rule 2 — Approved Licenses Only

All dependencies must use one of these licenses:

| License | Status |
|---------|--------|
| MIT | ✅ Approved |
| Apache 2.0 | ✅ Approved |
| BSD 2-Clause / BSD 3-Clause | ✅ Approved |
| ISC | ✅ Approved |
| Python Software Foundation (PSF) | ✅ Approved |
| LGPL | ⚠️ Lead approval required |
| GPL (any version) | ❌ Not approved — copyleft conflicts with commercial use |
| AGPL | ❌ Not approved |
| Commercial / proprietary | ❌ Not approved without legal review |

---

## Rule 3 — Justify Every New Package

When adding a package, your PR description must answer:

1. **What does it do?** — one sentence
2. **Why can't existing packages handle this?** — checked FastAPI, LangGraph, Pydantic, etc.
3. **CVE status** — paste `pip-audit` or `npm audit` output
4. **License** — confirm it's in the approved list above

---

## Rule 4 — Pin Exact Versions in Production

- `pyproject.toml` uses `>=` ranges for dev flexibility
- `uv.lock` (generated by `uv sync`) pins exact versions — commit this file
- Docker images use the locked versions — no `latest` tags for Python packages
- Renovate Bot (Phase 2) will auto-update with PR review — not yet active

---

## Rule 5 — Regular Audit Schedule

| When | What |
|------|------|
| Every push/PR | `pip-audit` + `npm audit` runs in CI (`security.yml`) |
| Daily at 02:00 UTC | CI re-runs against existing deps (catches new CVEs) |
| Before each Phase gate | Manual full audit + license check by Team 10 |
| Before production launch | `pip audit --fix` dry-run reviewed by lead |
